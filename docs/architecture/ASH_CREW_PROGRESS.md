## Gate 0 seam observations from current code

- AshConfig.load() resolves active_profile_name() from process environment / active-profile marker before reading selected profile TOML and dotenv. It merges explicit defaults with later environment and explicit overrides; a profile-specific database default is not a security ceiling. Concurrent coworker code must not rely on changing this selection globally.
- AshClient.create(config=..., session_id=...) can reuse an already resolved config and explicitly chosen session. Its client locks turns, while the SessionStore maintains a runtime lease; a canonical conversation should not be concurrently mutated by background runs.
- AshLoop tool dispatch first checks permission_policy.evaluate(tool_name, arguments), then optional on_tool_approval/UI approval, records the outcome, and only later marks record.dispatched. This is a candidate interception seam, not yet a durable approval suspension: the callback is not independently authenticated or persisted across restart.
- The existing scheduled automation runner loads a serialized config and creates AshClient without a chosen existing session for each run. It therefore does not provide coworker-owned longitudinal work by itself.
- The candidate seam must be tested across all consequential local, MCP and plugin paths before declaring Gate 4 approval/resume complete.

## Gate 1 runtime boundary checkpoint (2026-10-27)

This closes the demonstrated alternate entry point without enabling coworker execution.
- Registration remains provisioning only. The coworker creation regression now makes `ProviderRegistry.build()` fail if called, proving registration does not construct a model provider. It creates no model request and uses no real provider credentials.
- Runtime mapping: `build_runtime()` assembles `SandboxManager`, `SessionStore`, provider, policies, plugins, repo map/LSP, instructions, hooks, MCP, tools, memory, and `AshLoop` (`src/ash/runtime.py`). Provider factories are held by a process-global `ProviderRegistry`; fallback providers are eagerly constructed and readiness resolves provider-specific API keys and endpoints from ambient environment (`src/ash/providers/registry.py`, `provider_catalog.py`, `readiness.py`). Credential helpers later execute host commands; ChatGPT auth can select the active profile and read/refresh state below `Path.home()/.ash`; Google, AWS, and Azure SDK credential chains can consult ambient caches, metadata, or identity (`src/ash/providers/credential_helper.py`, `openai_chatgpt_auth.py`, and cloud provider modules).

Startup can create/open SQLite state, run session cleanup and plugin recovery, and initialize extension clients. `AshLoop.start()` starts MCP and recovers/leases sessions. Tool dispatch can write workspace files, run processes, call browser/web or MCP tools, launch plugin subprocesses, invoke hooks and callbacks, and mutate automation, agent, and memory state. ## Gate 1 child environment slice (2026-10-27)

- Scope: `src/ash/coworkers.py` now exposes an owner-keyed `CoworkerHandle.worker_process_environment()` context. It re-reads the stored owner/coworker binding, rejects a changed profile, workspace, canonical session, or non-ready identity, and refuses to create worker storage inside the bound workspace. Each context creates a temporary root under the Ash state directory with mode `0700` on POSIX, separate per-run home/config/data/cache/state/runtime/tmp/work paths, and cleanup when the context closes.
- This slice was developed against `feature/ash-crew` HEAD `84cdd69fb11b9114692c3e6a2fce69b95608216f`; the Codex handoff contained an uncommitted diff reviewed independently before acceptance.
- The yielded `CoworkerProcessEnvironment.as_environ()` returns a fresh allowlisted mapping. It sets HOME, XDG roots, temp paths, `PYTHONNOUSERSITE`, and `PYTHONDONTWRITEBYTECODE`; it does not inherit `ASH_PROFILE`, provider keys, cloud credential locations, proxies, `PATH`, or `PYTHONPATH`. Windows additionally receives USERPROFILE, APPDATA, LOCALAPPDATA, and the host SYSTEMROOT/WINDIR values needed by Windows process startup. The yielded value carries no workspace, session DB, provider, extension, callback, or approval objects, but the child still has the current user's OS filesystem and network permissions. The caller must keep it open until a child exits and launch a trusted executable by absolute path.
- This is a reusable environment primitive, not an OS sandbox or runtime admission path. Both workers run as the same OS user, so one can read the other's mode-`0700` directories. A child can also traverse to absolute filesystem paths, contact network and cloud metadata endpoints, use OS credential stores, and launch absolute executables. Workspace extensions and effects remain reachable to code that is given a workspace path. Python may add `LC_CTYPE` during startup; the test allows that locale normalization while checking that parent sentinels do not appear.
- Runtime map confirmed against current source: `build_runtime()` first checks the coworker refusal, then creates sandbox/session state, resolves permission rules and workspace trust, builds a provider from the process-global `ProviderRegistry` unless one is explicitly supplied, recovers and discovers user/project plugins, and loads repo map, LSP, instructions, hooks, MCP, tools, callbacks, and memory (`src/ash/runtime.py`). User plugins, agents, hooks, skills, MCP OAuth and ChatGPT auth use `Path.home()` roots; trusted workspace config adds project hooks/MCP/LSP/extensions. Provider readiness and pools read ambient environment, helpers launch host commands, ChatGPT auth selects the active profile below `Path.home()/.ash`, and Google/AWS/Azure SDKs can use default credential chains. Startup can open and clean session databases, recover plugin lifecycle, and initialize extension clients. `AshLoop.start()` starts MCP/session work. Later tools can write files, run commands, make web/browser/MCP calls, run plugin hooks/subprocesses, update agent/automation/memory state, and call host callbacks. Command sandboxing alone does not confine direct filesystem tools, provider clients, in-process callbacks, or every network path.
- Boundary choice: a scrubbed subprocess is a simpler first step than threading provider, credential, home, extension, and filesystem dependencies through the current in-process runtime. The process boundary can reset the environment and default home lookup in one place, but it does not provide a valid coworker runtime boundary until OS filesystem/network/process controls and authenticated owner/profile/config/session admission are in place. Owner IDs remain local lookup keys, not authenticated principals. In-process dependency injection would still need explicit controls for cloud SDK default chains and callbacks.
- No Ash runtime was assembled by this slice. `_require_runtime_available()` remains in shared `build_runtime()` and `AshClient.create()` paths; `CoworkerHandle.start_runtime()` still refuses. The deterministic child probe used only synthetic environment sentinels and Python's standard library. It created two coworker contexts concurrently, verified distinct temporary roots and `Path.home()`, `cwd`, and `tempfile.gettempdir()`, confirmed no `.ash` home or ambient sentinel values appeared, and confirmed temporary roots were removed and the parent environment stayed unchanged. It did not run a fake provider, open coworker sessions from a worker, or demonstrate a full worker-process restart.
- Verification under isolated HOME/XDG/TMPDIR and an external pytest basetemp: **17 selected tests passed in 2.28 s** across `tests/unit/test_coworkers.py`, `test_build_runtime_rejects_coworker_bound_config`, and `test_async_sdk_rejects_unisolated_auto_approve`. This includes identity/session restart tests, the two-process environment probe, workspace-storage refusal, and the direct runtime/SDK refusals. `ruff check src/ash/coworkers.py tests/unit/test_coworkers.py`, `mypy src/ash/coworkers.py`, `ruff format --check tests/unit/test_coworkers.py`, and `git diff --check` passed. A whole-file format check for `src/ash/coworkers.py` still reports two unchanged formatting differences already present at this base; no unrelated format changes were made. No full repository suite or live provider was run. The previous 481-test runtime-guard batch was not repeated.

Design a supervised worker admission boundary that authenticates the local owner, binds the explicit profile/config and separate session DB, and provides fail-closed OS filesystem, network, and process restrictions. Only then run two separate fake-provider Ash sessions concurrently and reopen them after a full worker-process restart. Continue to block live credentials, providers, plugins, MCP, cloud SDKs, callbacks, browser, LSP, and unrestricted host tools until each capability has explicit scoped authority and adversarial coverage. Do not begin event or approval gates yet.
